Omnific: Architecture Overview

A prompt-to-simulation platform. OpenAI agents research a scenario and build a physical model. Generated solver code runs in a sandbox, evaluators check the result, and Blender dresses the 3D scene. The user gets an interactive, honest simulation in the browser and as a .blend file.

1. Business Context

Objective

Turn any described physical event, like "an atomic bomb at a black hole's event horizon" or "a vacuum-tube computer adding numbers", into a simulation that is physically grounded and checked. The solver is the source of truth, never the renderer.

Users

  • Students and educators exploring physics
  • Engineers sketching what-if scenarios
  • Demo audiences browsing the public library
  • Reviewers who accept results or ask for changes

Value

  • Every result is labelled with its fidelity (analytic, validated numerical or heuristic)
  • Assumptions, cited sources and anything "not simulated as asked" are shown plainly
  • An interactive viewer with stages, key results and a Tune panel, plus the Ask tab

Quality signals

628 Python tests  ·  120+ web unit tests  ·  Playwright e2e on desktop and phone. The evaluator checks units, invariants, bounds, geometry, effects and bindings before a human review.

5. Features

Functional

  • Prompt, attachments and documents in; clarifying questions with defaults
  • Self-correcting model → code → run → check loop, with a human review
  • Interactive 3D with stages, explosions and effects, key results and charts
  • Pick each object's 3D model while the simulation builds
  • Tune values and compare runs; follow-up versions
  • Ask tab: questions about the run and the physics behind it
  • .blend export; public library; demo replay of saved prompts

Honesty

  • Fidelity badge, assumptions and sources on every result
  • "Not simulated as asked" notice for departures
  • "Not to scale" when something is drawn larger than life
  • Models face the right way: front and top detected, objects aimed at their targets

Non-functional

  • Generated code is sandboxed only; the AST guard covers Blender scripts
  • Strict JSON-schema contracts between every agent
  • Fail-open refinements: vision checks and dressing never sink a job
  • Durable workflows (Temporal on disk); services restart with Docker
  • Accessible UI, works at phone width, light and dark themes

Safety

  • Weapons and explosions are modelled only as impact and blast physics
  • Licence filter: CC0 and CC-BY only, with credits in the scene
  • Tokens are sent only to their own API host; secrets live only in .env

6. Deployment

Local (Docker Compose)

setup.ps1 on Windows or ./setup.sh on macOS and Linux. Each one checks Docker, writes .env (with the keys typed hidden), builds the images, starts the stack and waits until the API and site respond, then opens the site.

web :3000api :8000 Temporal UI :8233S3 :9000Postgres :5432

Cloud (prepared, not deployed)

Helm chart and Terraform for GKE (EKS and AKS planned): one deployment per worker, the sandbox on the Kubernetes API with gVisor, an optional GPU node pool for 3D generation.

Prerequisites

  • Docker Desktop, or Docker Engine with Compose v2
  • An OpenAI API key (optional: a Sketchfab token)
  • For development: uv with Python 3.11, and Node.js LTS (setup.bat)
